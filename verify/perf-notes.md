# Four-wall performance

Run `npx tsc --noEmit && npx vite build --outDir dist-perf`, preview on port 4175, then `VERIFY_URL=http://localhost:4175/ node verify/four-wall-perf.mjs after`. The script uses an already installed Puppeteer (or `PUPPETEER_PATH`) and Playwright's existing Chromium executable; it installs nothing. `before` records the baseline without applying performance assertions. The final `after` invocation prints both saved baseline and new breakdowns and writes `perf-evidence.txt`.

The four-wall mouse/orbit/drain/Space flow matches edges.mjs. Measurements use 1920×1080, DPR 1.5, real WebGPU/Metal, without screenshot readbacks during sampling. Airborne samples cover 0.1–2 seconds after Space; settled samples cover 8–10 seconds. FPS is the median of actual frame intervals, not the HUD's smoothed estimate. CPU category values are per-frame means. Rapier is included in physics; shadow submission is included in render; GC overlaps CPU categories. Render means CPU submission, not GPU execution. CDP MinorGC/MajorGC events on the renderer main thread are aligned to performance.now() using a trace timestamp. Positive heap deltas are a pressure estimate, not an exact allocation count. Raw frames and GC events are retained alongside each measurements.json.

Opt-in `?fourWallPerf` instrumentation is in four-wall-metrics.ts and the permitted physics/tank/spill/rewind/post modules; the shared aquarium loop was not edited. Normal presentation does not collect timing samples or enable native profiling.

The initial source already used 60 Hz glass physics. The crowded-world 48/12 solver escalation plus three catch-up ticks was the dominant regression (145.1 ms physics/frame). A 12/4, two-tick trial reached only 20.1 FPS. Native profiling of the 4/1, two-tick trial identified collision detection as the largest Rapier category (11.4 ms/frame versus 2.8 ms solver); iteration reduction alone was insufficient. Crowded worlds now use 4/1 and at most one tick per frame, dropping overdue whole ticks; small worlds retain 12/4 and at most two ticks. Overload can intentionally slow physics instead of accumulating catch-up work. The 60 Hz step and seeded release remain unchanged, and the library verifies deterministic chunking and both backlog caps.

Loose glass was already one merged, triangle-sorted mesh, not separate draws or instancing, and does not cast shadows. Its material, geometry, launch impulses and triangle sorting are unchanged. Cached poses avoid repeating vertex transforms for stationary shards; unchanged batches avoid vertex/normal/index uploads. Sleeping bodies synchronize their final pose once, including both interpolation endpoints so a subsequent native wake cannot interpolate from a stale pose; a focused library regression protects this. Rewind still captures at 30 Hz; direct typed-array pose writes eliminate temporary pose arrays. Spill reuses vector storage and stops rebuilding invisible dry sheets. Native sleep is retained; no new forced-sleep deadline was added.

Other agents changed the lighting concurrently: the baseline had 50 total/15 shadow draws and the final build 49 total/10 shadow draws. Intermediate builds had 69/30. The render submission timings therefore describe the actual respective builds, not a controlled lighting comparison. Physics remains the measured dominant improvement.

Evidence: perf-before/measurements.json, perf-after/measurements.json, perf-evidence.txt; perf-library.txt, perf-edges.txt, perf-lab.txt and perf-runtime.txt. The original shatter-airborne.png is preserved under perf-before/. Runtime is executed last so verify/shatter-airborne.png represents the final tested build.

Final runtime passed after one invocation, executed last. Visual comparison of perf-before/shatter-airborne.png and perf-after/shatter-airborne.png preserves the shatter geometry, translucency, glints and burst style; timing shifts some poses slightly, and concurrent lighting/UI edits change the surrounding scene. Raw four-wall frames from 5.0–5.1 seconds report zero awake shards in all six samples.
