## Method and reproduction

- `burst-compare.mjs`: Playwright/WebGPU,1600×1000,DPR1.5; fresh page per case. Lab reset while frozen, default camera, centre click rounded to[0.02,0.01], then unfreeze. Main default camera and pristine Space at[0.6,1.81,2.2]. All profiles share rendering, fracture geometry and release code.
- `?physics=legacy&burstProbe` reconstructs the saved pre-performance physics. `?burst=before&burstProbe` reproduces the pre-fix launch gating; default launch uses the fix. The independent reproduction in `burst-reference.mjs` imports the actual saved `verify/perf-before/physics.ts.txt` copied verbatim to `burst-reference-physics.ts`. It compares all first30 step positions/velocities against the runtime reconstruction at220 cells and the fixed launch at600 cells. Both levels pass bit-for-bit.
- Times0.1/0.25/0.5 are elapsed solver time: exactly6/15/30 steps at60Hz. Outward velocity is signed `dot(linvel,normalize(worldCom-impact))` in3D, recomputed per body per step. The outward fraction counts positive values. Percentiles use sorted index floor((n-1)*p). No area/mass weighting or virtual compounds alter body metrics. Gravity is included in the measured velocity.
- Each raw `burst-{reference,before,after}/{L2,L3,main}.json` stores every body's COM, linear/angular velocity and sleep status after each step, and the damping regime actually used before each step. It also stores solver/PGS settings, extra per-body iterations, cached-pose state, render frame IDs, wall timestamps and actual step counts. The corresponding600-count directories hold the dense checks.
- Damping regimes are airborne0.45/1.2, supported3/1 (Lab/reference main) or6/5 (individual main), and quiet8/20. First-step support count is zero in every run. Support requires an upward manifold against a marked floor/plinth or a grounded, nearly stationary neighbour; touching the frame or another airborne shard is not support.
- Each run advances30 steps over0.5 simulated seconds. The raw frames also report actual wall-time progress, including release/render stalls. At600 cells these clocks differ materially: the first frame can stall, and the loop clamps frame dt before bounded catch-up. The evidence lists steps completed in the first0.5 wall seconds separately. These wall counts are scheduling-sensitive; they are not used to claim deterministic trajectories.
- `RUNS=reference,before,after VERIFY_URL=http://localhost:4175/ node verify/burst-compare.mjs`; dense runs use `COUNT=600 CASES=L2,L3 RUNS=reference600,before600,after600`. `burst-performance.mjs` measures the unchanged main four-wall flow with the existing performance probe and no per-body burst probe, over wall-time0.1–1.5s airborne/8–10s settled,1920×1080,DPR1.5.
- Screenshots use fresh default Lab L3 pages at exact solver times0.15/0.4. The optional probe freezes at the requested tick and presents that exact body pose, avoiding render-frame interpolation differences. JSON beside each image records elapsed time and all displayed transforms. The default-count burst reads the same in the paired images; the fix is not claimed to make it more explosive.
